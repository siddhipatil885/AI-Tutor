# Data Split and Leakage Prevention Report

## 1. Investigation of Dataset Leakage
We thoroughly investigated the `corrupted_codes_best` generation output to determine how examples map to underlying structures:
- **Duplicate Code**: There were exactly 625 samples featuring exact duplicate generated code (either within the same run or sampled identically). These duplicates have been entirely **removed** to prevent identical source codes from appearing across Train and Test splits.
- **Problem Association**: Different problems exercise different misconceptions. While several misconceptions use the same problem IDs, preventing leakage at the problem level is not strictly required because the model's job is precisely to learn which misconception is present in a generalized context.
- **The Split Strategy**: Because exact duplicate code has been deduplicated, splitting the remainder purely via stratified splits along the target `global_misconception_index` ensures no direct code leakage.

## 2. Train/Validation/Test Strategy
The dataset has an extreme class imbalance across its 67 classes.

- **Class Constraint**: Classes with fewer than 10 examples (there are 13 such rare classes) cannot be reliably stratified into an 80/10/10 split without breaking split bounds (creating 0-element validation sets). 
- **Rare Class Preservation**: To ensure the model still trains on these rare categories, all 13 of these rare classes were pushed exclusively into the **Train** set.
- **Standard Split**: The remaining robust classes were stratified using an 80/10/10 Train/Validation/Test split with a fixed random seed (`42`).

### Final Split Sizes
- **Train Size**: 854 examples
- **Validation Size**: 98 examples
- **Test Size**: 98 examples

*Total usable examples after deduplication and filtering: 1,050*

## 3. Label Leakage Prevention
As strictly required, the following preventative measures were taken:
- The `reasoning` trace generated by the LLM was entirely excluded from the feature space, preventing the model from reading explicit textual hints about the misconception class.
- The `global_misconception_index` has been designated exclusively as the target label.

The test set remains isolated in `ml/data/processed/test.csv`.
